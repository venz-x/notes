Section 1

Computer architecture and its block diagram

Scope

Define level, not depth. Know what each part is and what it does. Hardware internals are not needed.

What is computer architecture?

Computer architecture is the conceptual design and fundamental operational structure of a computer system. It describes which hardware components exist, how they are connected, and how together they fetch and execute instructions. It answers “what does the machine look like to the programmer and how do the parts cooperate?” and leaves “how are the transistors wired?” to circuit design.

Block diagram

Role of each block

BlockRole
InputBrings programs and data into the computer from the outside world (keyboard, mouse, disk, sensors).
MemoryStores the program instructions and the data they work on, in numbered cells (addresses).
ALU (Arithmetic Logic Unit)Performs the actual computing: arithmetic (add, subtract) and logic (AND, OR, compare). It also reports status flags (zero, carry, overflow, negative) back to Control.
Control (Control Unit)The conductor. It fetches and decodes each instruction and sends control signals telling every other block what to do and when.
OutputDelivers results to the outside world (screen, printer, speaker, disk).

Together, the Control unit and the ALU (plus registers) form the CPU, the processor.

The ALU → Control arrow: status flags

Control tells the ALU what to do, but sometimes Control must know what happened before it can choose the next step. After each operation the ALU sends back small yes/no signals called status flags:

FlagSet to 1 when
Zerothe result is 0
Negativethe result is negative
Carryan addition produced a carry out of the top bit
Overflowthe result is too large to fit in the register

How the blocks work together: example operations

Every instruction goes through the same fetch → decode → execute cycle, driven by Control. The registers from Section 2 hold the values passing between the blocks.

Example A: ADD X (add the number stored at address X to AC). Suppose AC = 5 and Memory[X] = 3.

StepWhat happensBlocks and registers involved
1. FetchThe address in PC is copied to MAR. Control sends a read signal. The instruction ADD X comes back through MDR into IR. PC moves on to the next instruction.Control → Memory (dashed); Memory → MDR → IR (data); PC, MAR
2. DecodeControl reads the opcode in IR and works out: “add, with the operand at address X.”Control, IR
3. Get operandX is placed in MAR. Control sends another read signal. The value \(3\) arrives in MDR.Control → Memory; Memory → MDR
4. ExecuteControl tells the ALU to add. The ALU takes AC \((5)\) and MDR \((3)\) and stores \(5+3=8\) back in AC.Control → ALU (dashed); MDR, AC ↔ ALU (data)
5. ReportThe ALU sends its flags to Control: Zero = 0, Negative = 0, Carry = 0, Overflow = 0.ALU → Control (status flags)

Example B: a conditional jump, “if AC equals 5, jump to address T”. This is where the ALU → Control arrow matters.

StepWhat happens
1Fetch and decode the compare/jump instruction, as in Example A.
2Control tells the ALU to subtract 5 from AC. With AC = 5 the ALU computes \(5-5=0\).
3The ALU sends the Zero flag = 1 to Control.
4Control sees Zero = 1, so the condition is true and it loads T into PC. The next fetch starts at T. If Zero had been 0, PC would be left alone and the program would continue in order.

Example C: input and output. To read a value, Control signals Input to send it, and it is stored in Memory. To show a result, Control signals Memory to send the value to Output. Data moves along the solid arrows and Control triggers each move with the dashed ones.

Section 2

Registers

Scope

Definition and just know. Nothing else is needed.

A register is a tiny, very fast storage cell inside the CPU. Five special-purpose registers to know:

RegisterNameDefinition
PCProgram CounterHolds the memory address of the next instruction to be fetched and executed.
IRInstruction RegisterHolds the current instruction being decoded and executed.
MARMemory Address RegisterHolds the memory address from which data will be fetched or to which data will be written.
MDRMemory Data RegisterHolds the actual data being transferred to or from memory.
ACAccumulatorTemporarily stores intermediate arithmetic and logic results from the ALU.

Memory trick: MAR = where (address), MDR = what (data).

Section 3

The system bus

A bus is a shared communication pathway, a set of parallel wires, that connects the CPU, memory and I/O devices. The system bus is made of three groups of lines.

BusCarriesDirection
Address busThe memory or I/O address being accessed (the “where”).One way, CPU → memory / I/O
Data busThe actual data or instruction being moved (the “what”).Two way
Control busControl and timing signals such as read, write and clock.Mostly from the CPU, with some status lines back

Section 4

Von Neumann architecture vs. Harvard architecture

Von Neumann architecture

A single shared memory (and a single bus) holds both program instructions and data. The CPU fetches an instruction, then fetches or stores data, all through the same path.

Harvard architecture

Instruction memory and data memory are separate, each with its own bus to the CPU. The CPU can therefore fetch the next instruction while it reads or writes data.

Advantages and disadvantages

Von NeumannHarvard
Memory / bus structureOne memory space and one bus for instructions and data.Two separate memories and two buses.
SpeedInstruction fetch and data access compete for the same bus. This is the Von Neumann bottleneck.Instruction and data can be accessed simultaneously, so it is faster per cycle.
Hardware complexity and costSimpler and cheaper (one memory, one bus).More complex and costly (two memories, two buses, more pins).
FlexibilityMemory is shared flexibly between code and data; programs can be loaded and even modified like data.Fixed split. Spare data memory cannot be used for code and vice versa.
Typical useGeneral-purpose computers (PCs, laptops, servers).Microcontrollers and DSPs (signal-processing chips).

Section 5

Seven great ideas in computer architecture

The lecture introduction lists seven big ideas that shape almost every modern computer design.

#IdeaMeaningExample
1AbstractionHide lower-level hardware details behind simpler high-level interfaces to manage complexity.A program uses an instruction set without knowing the transistors.
2Make the common case fastOptimizing frequent operations gives far greater overall speedup than optimizing rare ones.Fast integer add, since adds are very common (this is Amdahl’s law, Section 9).
3ParallelismPerform multiple operations at the same time to boost performance.Multi-core processors, instruction-level parallelism.
4PipeliningOverlap the execution stages of several instructions, like an assembly line, to raise instruction throughput.While one instruction executes, the next is decoded and a third is fetched.
5PredictionGuess an outcome ahead of time rather than wait for it, to avoid pipeline stalls.Branch prediction.
6Hierarchy of memoriesOrganize memory in layers so the fastest, smallest memory is closest to the CPU and larger, cheaper memory holds bulk data.Registers → Cache → RAM → Storage.
7Dependability via redundancyInclude backup components so the system keeps working reliably if one fails.RAID disks, ECC memory.

Section 6

Understanding performance

Two core metrics

MetricMeaningQuestion it answers
Response time (execution time)Total time to complete one task.“How long do I wait?”
Throughput (bandwidth)Total work (tasks or instructions) completed per unit of time.“How much gets done per second?”

Response time splits into two parts:

$$\text{Response Time}=\text{CPU Time}+\text{I/O Time}$$
  • I/O time: disk, memory, network and operating-system overhead.
  • CPU time: the time the processor actually spends computing the task.

Core formulas

$$\text{Performance}=\frac{1}{\text{Execution Time}}\qquad\qquad \text{Throughput}=\frac{N}{T}$$

where \(N\) is the number of tasks (or instructions) and \(T\) is the total (CPU) time. Higher performance and higher throughput are both better, and a smaller time means a higher performance.

To say “A is \(n\) times faster than B”: \(\dfrac{\text{Performance}_A}{\text{Performance}_B}=\dfrac{\text{Time}_B}{\text{Time}_A}=n\).

Problem 1From class notes · completed

Processor A executes \(600\) million instructions in \(0.3\) sec. Processor B executes \(5\) billion instructions in \(2.5\) sec. Find the throughput of each and compare them.

Solution

$$\text{Throughput}=\frac{N}{T}$$
$$\text{Throughput}_A=\frac{600\times10^{6}}{0.3\ \text{sec}}=\frac{6\times10^{8}}{3\times10^{-1}}=2\times10^{9}\ \text{instructions/sec}$$
$$\text{Throughput}_B=\frac{5\times10^{9}}{2.5\ \text{sec}}=2\times10^{9}\ \text{instructions/sec}$$
Conclusion: \(\text{Throughput}_A=\text{Throughput}_B=\boxed{2\times10^{9}\ \text{instructions/sec}}\). Both processors have equal throughput.

Correction to the handwritten note

The note for A showed \(2\times10^{7}\). The correct value is \(2\times10^{9}\): \(600\times10^{6}=6\times10^{8}\), and dividing by \(0.3\) multiplies by about \(3.33\), giving \(2\times10^{9}\). B’s line was left blank and is completed above.

Problem 2From class notes · completed

Processor A executes a task in \(10\) sec and Processor B executes it in \(15\) sec. Find the performance of each and decide which is better.

Solution

$$\text{Performance}=\frac{1}{\text{Execution Time}}$$
$$\text{Performance}_A=\frac{1}{10}=0.1\ \text{sec}^{-1}\qquad\text{Performance}_B=\frac{1}{15}\approx0.067\ \text{sec}^{-1}$$
Conclusion: \(0.1\gt0.067\), so Processor A has better performance. Check: \(\dfrac{0.1}{0.067}=\dfrac{15}{10}=1.5\), so A is \(1.5\times\) faster than B.
Extra ExampleThroughput

Processor X executes \(900\) million instructions in \(0.45\) sec. Processor Y executes \(3\) billion instructions in \(2\) sec. Which has the higher throughput?

Solution

$$\text{Throughput}_X=\frac{900\times10^{6}}{0.45\ \text{sec}}=\frac{9\times10^{8}}{4.5\times10^{-1}}=2\times10^{9}\ \text{instructions/sec}$$
$$\text{Throughput}_Y=\frac{3\times10^{9}}{2\ \text{sec}}=1.5\times10^{9}\ \text{instructions/sec}$$
Conclusion: \(2\times10^{9}\gt1.5\times10^{9}\), so X has the higher throughput, \(\dfrac{2}{1.5}\approx1.33\times\) that of Y.
Extra ExamplePerformance

A task takes \(4\) sec on Processor P and \(8\) sec on Processor Q. Compare their performance.

Solution

$$\text{Performance}_P=\frac{1}{4}=0.25\ \text{sec}^{-1}\qquad\text{Performance}_Q=\frac{1}{8}=0.125\ \text{sec}^{-1}$$
$$\frac{\text{Performance}_P}{\text{Performance}_Q}=\frac{0.25}{0.125}=2$$
Conclusion: P is \(2\times\) faster than Q.

Section 7

CPU time and clock rate

The three-step formula chain

$$\text{CPU Time}=\text{CPU Clock Cycles}\times\text{Clock Cycle Time}$$
$$\text{CPU Time}=\frac{\text{CPU Clock Cycles}}{\text{Clock Rate}}$$
$$\text{CPU Time}=\frac{\text{IC}\times\text{CPI}}{\text{Clock Rate}}$$

How the chain connects: the clock cycle time is the reciprocal of the clock rate, \(\text{Clock Cycle Time}=\dfrac{1}{\text{Clock Rate}}\), which turns line 1 into line 2. The total clock cycles equal \(\text{IC}\times\text{CPI}\), which turns line 2 into line 3.

TermMeaningUnit
ICInstruction Count: how many instructions the program executes.instructions
CPICycles Per Instruction: average clock cycles each instruction takes.cycles/instruction
Clock rateCycles per second.Hz  (\(1\ \text{MHz}=10^{6}\ \text{Hz}\), \(1\ \text{GHz}=10^{9}\ \text{Hz}\))
Clock cycle timeDuration of one cycle, \(1/\text{Clock Rate}\).sec
Problem 3From class notes · completed

A processor executes \(800\) million instructions with a CPI of \(2\) and a clock rate of \(2\ \text{GHz}\) (\(2\times10^{9}\ \text{Hz}\)). Find the CPU time.

Solution

$$\text{CPU Time}=\frac{\text{IC}\times\text{CPI}}{\text{Clock Rate}}$$
$$\text{CPU Time}=\frac{800\times10^{6}\times2}{2\times10^{9}\ \text{Hz}}=\frac{1.6\times10^{9}}{2\times10^{9}}\ \text{sec}$$
\(\text{CPU Time}=\boxed{0.8\ \text{sec}}\)
Problem 4From class notes · completed and corrected

A program has \(1200\) instructions. Processor A has \(\text{CPI}=2\) and clock rate \(2\ \text{GHz}\) (\(2\times10^{9}\ \text{Hz}\)). Processor B has \(\text{CPI}=1.5\) and clock rate \(2.5\ \text{MHz}\) (\(2.5\times10^{6}\ \text{Hz}\)). Find the CPU time of each and decide which is better.

Solution

$$\text{CPU Time}=\frac{\text{IC}\times\text{CPI}}{\text{Clock Rate}}$$
$$\text{CPU Time}_A=\frac{1200\times2}{2\times10^{9}\ \text{Hz}}=\frac{2400}{2\times10^{9}}=1.2\times10^{-6}\ \text{sec}=1.2\ \mu\text{s}$$
$$\text{CPU Time}_B=\frac{1200\times1.5}{2.5\times10^{6}\ \text{Hz}}=\frac{1800}{2.5\times10^{6}}=7.2\times10^{-4}\ \text{sec}=720\ \mu\text{s}$$
Conclusion: \(1.2\ \mu\text{s}\lt720\ \mu\text{s}\), so Processor A is better. It is \(\dfrac{7.2\times10^{-4}}{1.2\times10^{-6}}=600\times\) faster.

Correction to the handwritten note

In the scratch work the values \(1.5\) and \(2.5\) were swapped in B’s fraction. The CPI (\(1.5\)) belongs in the numerator with IC, and the clock rate (\(2.5\ \text{MHz}\)) belongs in the denominator. Also watch the unit: B’s clock is in MHz (\(10^{6}\)), not GHz.

Extra ExampleCPU time

A program has \(500\) million instructions, \(\text{CPI}=3\), and runs on a \(1.5\ \text{GHz}\) processor. Find the CPU time and the clock cycle time.

Solution

$$\text{CPU Time}=\frac{\text{IC}\times\text{CPI}}{\text{Clock Rate}}=\frac{500\times10^{6}\times3}{1.5\times10^{9}}=\frac{1.5\times10^{9}}{1.5\times10^{9}}=\boxed{1\ \text{sec}}$$
$$\text{Clock Cycle Time}=\frac{1}{\text{Clock Rate}}=\frac{1}{1.5\times10^{9}}\approx0.667\times10^{-9}\ \text{sec}=0.667\ \text{ns}$$
Extra ExampleCPU time and CPI, two processors

A program has \(2000\) instructions. Processor X: \(\text{CPI}=1.2\), \(3\ \text{GHz}\). Processor Y: \(\text{CPI}=2\), \(4\ \text{GHz}\). Which is faster, and by what factor?

Solution

$$\text{CPU Time}_X=\frac{2000\times1.2}{3\times10^{9}}=\frac{2400}{3\times10^{9}}=8\times10^{-7}\ \text{sec}=0.8\ \mu\text{s}$$
$$\text{CPU Time}_Y=\frac{2000\times2}{4\times10^{9}}=\frac{4000}{4\times10^{9}}=1\times10^{-6}\ \text{sec}=1\ \mu\text{s}$$
Conclusion: X is faster even though Y has the higher clock rate. \(\dfrac{1.0}{0.8}=1.25\times\). A higher clock does not guarantee better performance when CPI differs.

Section 8

Speedup and performance scaling

Speedup formula

$$\text{Speedup}=\frac{\text{Old Time}}{\text{New Time}}\quad(\times)$$

Equivalently \(\text{Speedup}=\dfrac{\text{Performance}_{\text{new}}}{\text{Performance}_{\text{old}}}\). A speedup above \(1\times\) means an improvement.

Problem 5From class notes · cleaned up

A processor executes a fixed workload (\(2\) million instructions) at an initial clock rate of \(2000\ \text{Hz}\). The clock rate is now increased to \(4000\ \text{Hz}\). Calculate the speedup.

Solution

$$\text{CPU Time}_{\text{old}}=\frac{\text{IC}\times\text{CPI}}{2000}\qquad\text{CPU Time}_{\text{new}}=\frac{\text{IC}\times\text{CPI}}{4000}$$
$$\text{Speedup}=\frac{\text{CPU Time}_{\text{old}}}{\text{CPU Time}_{\text{new}}}=\frac{\dfrac{\text{IC}\times\text{CPI}}{2000}}{\dfrac{\text{IC}\times\text{CPI}}{4000}}=\frac{4000}{2000}$$
\(\text{Speedup}=\boxed{2\times}\). The workload and CPI are unchanged, so they cancel. Doubling the clock rate halves the time.

(Illustration: if \(\text{CPI}=1\), the old time is \(\dfrac{2\times10^{6}}{2000}=1000\ \text{sec}\) and the new time is \(500\ \text{sec}\), and \(\dfrac{1000}{500}=2\).)

Problem 6From class notes · completed

Computer A has a clock rate of \(2\ \text{GHz}\) and a CPU time of \(10\) sec. Computer B aims for a CPU time of \(6\) sec, and its total clock cycles are \(20\%\) higher (\(\text{Clock Cycles}_B=1.2\times\text{Clock Cycles}_A\)). Find the clock rate Computer B needs.

Solution

Step 1. Clock cycles of A, using \(\text{CPU Time}=\dfrac{\text{Clock Cycles}}{\text{Clock Rate}}\Rightarrow\text{Clock Cycles}=\text{CPU Time}\times\text{Clock Rate}\):

$$\text{Clock Cycles}_A=10\ \text{sec}\times2\times10^{9}\ \text{Hz}=20\times10^{9}\ \text{cycles}$$

Step 2. Clock cycles of B (\(20\%\) more):

$$\text{Clock Cycles}_B=20\times10^{9}+\left(20\times10^{9}\times\frac{20}{100}\right)=20\times10^{9}+4\times10^{9}=24\times10^{9}\ \text{cycles}$$

Step 3. Required clock rate of B:

$$\text{Clock Rate}_B=\frac{\text{Clock Cycles}_B}{\text{CPU Time}_B}=\frac{24\times10^{9}}{6\ \text{sec}}=4\times10^{9}\ \text{Hz}$$
\(\text{Clock Rate}_B=\boxed{4\ \text{GHz}}\), twice the clock rate of A. B does \(20\%\) more work in \(60\%\) of the time, so it needs \(\dfrac{1.2}{0.6}=2\times\) the clock.

Correction to the handwritten note

The rough note wrote GHz where the result is a number of cycles. Cycles \(=\) seconds \(\times\) Hz, so the unit of \(20\times10^{9}\) is cycles.

Problem 7From class notes · completed

A processor’s performance is increased by \(50\%\). The original CPU time is \(10\) sec. Find the new CPU time.

Solution

$$\text{Performance}_{\text{old}}=\frac{1}{10\ \text{sec}}=0.1$$
$$\text{Performance}_{\text{new}}=\frac{1}{10}+\left(\frac{1}{10}\times\frac{50}{100}\right)=0.1+0.05=0.15$$
$$\text{CPU Time}_{\text{new}}=\frac{1}{\text{Performance}_{\text{new}}}=\frac{1}{0.15}$$
\(\text{CPU Time}_{\text{new}}=\boxed{6.67\ \text{sec}}\). Note that a \(50\%\) performance gain is a speedup of \(1.5\times\), so \(\dfrac{10}{1.5}=6.67\ \text{sec}\), not \(5\) sec.
Extra ExampleClock rate scaling

Computer X has a \(3\ \text{GHz}\) clock and a CPU time of \(12\) sec. Computer Y must finish the same program in \(8\) sec, but its total clock cycles are \(25\%\) higher. Find Y’s required clock rate.

Solution

$$\text{Clock Cycles}_X=12\times3\times10^{9}=36\times10^{9}\ \text{cycles}$$
$$\text{Clock Cycles}_Y=1.25\times36\times10^{9}=45\times10^{9}\ \text{cycles}$$
$$\text{Clock Rate}_Y=\frac{45\times10^{9}}{8\ \text{sec}}=5.625\times10^{9}\ \text{Hz}$$
\(\text{Clock Rate}_Y=\boxed{5.625\ \text{GHz}}\)
Extra ExampleSpeedup from a performance gain

A processor’s performance rises by \(25\%\). Its original CPU time is \(20\) sec. Find the new CPU time and the speedup.

Solution

$$\text{Performance}_{\text{old}}=\frac{1}{20}=0.05\qquad\text{Performance}_{\text{new}}=0.05+\left(0.05\times\frac{25}{100}\right)=0.0625$$
$$\text{CPU Time}_{\text{new}}=\frac{1}{0.0625}=16\ \text{sec}\qquad\text{Speedup}=\frac{20}{16}=1.25\times$$
\(\text{CPU Time}_{\text{new}}=\boxed{16\ \text{sec}}\), \(\text{Speedup}=\boxed{1.25\times}\)

Section 9

Pitfall: Amdahl’s law

Amdahl’s law

$$\text{Overall Speedup}=\frac{1}{(1-P)+\dfrac{P}{S}}$$
  • \(P\): the portion (fraction) of the program’s execution time that is improved or changed.
  • \(S\): the speedup factor of that improved part.
  • \(1-P\): the part that is not improved.

The pitfall. It is tempting to expect that making one component \(S\) times faster makes the whole system \(S\) times faster. It does not. The unimproved fraction \((1-P)\) still takes the same time, so it limits the total gain. Even an infinitely fast improvement is capped at \(\dfrac{1}{1-P}\).

Improved fraction \(P\)Best possible overall speedup \(\dfrac{1}{1-P}\)
\(0.50\)\(2\times\)
\(0.80\)\(5\times\)
\(0.90\)\(10\times\)
\(0.95\)\(20\times\)

This is why “make the common case fast” works: a large \(P\) is what lets an improvement pay off.

Problem 8From class notes · completed

A program spends \(50\%\) of its time on multiplication. A processor upgrade makes multiplication \(5\times\) faster. Find the overall speedup.

Solution

\(P=0.5\), \(S=5\).

$$\text{Overall Speedup}=\frac{1}{(1-0.5)+\dfrac{0.5}{5}}=\frac{1}{0.5+0.1}=\frac{1}{0.6}$$
\(\text{Overall Speedup}\approx\boxed{1.67\times}\), far below the \(5\times\) the multiplier alone gained.
Problem 9From class notes · completed

A program takes \(200\) sec to execute. \(60\%\) of the time is CPU calculation and \(40\%\) is memory access. The CPU improves the calculation part to be \(8\times\) faster. Find the overall speedup and the new execution time.

Solution

\(P=0.6\) (calculation is improved), \(S=8\).

$$\text{Overall Speedup}=\frac{1}{(1-0.6)+\dfrac{0.6}{8}}=\frac{1}{0.4+0.075}=\frac{1}{0.475}\approx2.105\times\ (\approx2.10\times)$$
$$\text{Speedup}=\frac{\text{Old Time}}{\text{New Time}}\ \Rightarrow\ \text{New Time}=\frac{\text{Old Time}}{\text{Speedup}}=\frac{200}{2.105}\approx95\ \text{sec}$$
\(\text{Overall Speedup}\approx\boxed{2.10\times}\), \(\text{New Time}\approx\boxed{95\ \text{sec}}\)

Direct check: \(200\times0.4+\dfrac{200\times0.6}{8}=80+15=95\ \text{sec}\). The notes’ \(95.24\ \text{sec}\) comes from rounding the speedup to \(2.10\) before dividing (\(\dfrac{200}{2.10}=95.24\)). The unrounded value is exactly \(95\ \text{sec}\).

Problem 10From class notes · derivation completed

A program spends \(80\%\) of its time in floating-point operations. Suppose the floating-point unit becomes infinitely fast (\(S\to\infty\)). Prove that the maximal overall speedup is \(5\times\).

Proof

$$\text{Overall Speedup}=\frac{1}{(1-P)+\dfrac{P}{S}}$$
$$\text{As }S\to\infty,\quad\frac{P}{S}\to0\ \Longrightarrow\ \text{Maximal Overall Speedup}=\frac{1}{1-P}$$
$$\text{Substituting }P=0.8:\quad\frac{1}{1-0.8}=\frac{1}{0.2}=5\times$$
Proved: \(\text{Maximal Overall Speedup}=\boxed{5\times}\). The remaining \(20\%\) of the time (the non-floating-point work) is untouched, so it caps the gain.
Extra ExampleAmdahl’s law

A program spends \(40\%\) of its runtime in a loop that a new accelerator makes \(10\times\) faster. Find the overall speedup.

Solution

$$\text{Overall Speedup}=\frac{1}{(1-0.4)+\dfrac{0.4}{10}}=\frac{1}{0.6+0.04}=\frac{1}{0.64}=1.5625$$
\(\text{Overall Speedup}\approx\boxed{1.56\times}\). A \(10\times\) faster part gives under \(1.6\times\) overall.
Extra ExampleAmdahl’s law with execution time and limit

A program takes \(120\) sec. \(75\%\) of its time is in a part that becomes \(3\times\) faster. Find the overall speedup, the new execution time, and the maximum speedup possible if that part were infinitely fast.

Solution

$$\text{Overall Speedup}=\frac{1}{(1-0.75)+\dfrac{0.75}{3}}=\frac{1}{0.25+0.25}=\frac{1}{0.5}=2\times$$
$$\text{New Time}=\frac{120}{2}=60\ \text{sec}\qquad\text{Maximum}=\frac{1}{1-0.75}=\frac{1}{0.25}=4\times$$
\(\text{Speedup}=\boxed{2\times}\), \(\text{New Time}=\boxed{60\ \text{sec}}\), limit \(=\boxed{4\times}\).
