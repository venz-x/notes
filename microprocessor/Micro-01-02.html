Module 1

Number systems and why memory is 8 bits wide

Base and radix

The base, also called the radix, is the number of unique digits a positional number system uses. A digit’s value depends on its position, and each position is worth the base times the position to its right. Microprocessor work uses four systems.

(1101)2 = 1×23 + 1×22 + 0×21 + 1×20 = 8 + 4 + 0 + 1 = 13

Why bits? Voltage levels in hardware

A CMOS transistor circuit does not measure a number, it only tells two voltage ranges apart. With a 1.0 V supply, an input between 0 V and 0.3 V counts as logic 0 and an input between 0.8 V and 1.0 V (up to VDD) counts as logic 1. The band from 0.3 V to 0.8 V is the forbidden zone. Signals only pass through it while switching, and a level that stays there is not a valid bit. The gap between the two valid bands is what lets a signal pick up some electrical noise and still be read correctly.

The voltages above are the ones used in the lecture. Real chips set their thresholds as fractions of whatever supply voltage they use, but the three-band picture is the same.

Why 8 bits?

Microprocessor memory is byte-addressable. It is laid out as a stack of cells, each with its own address, and the smallest cell the processor can address holds 8 bits (1 byte). Every value written to memory therefore occupies at least one full 8-bit cell.

That is why (7)10 = 1112 is stored as 00000111. The three significant bits go at the right and the five unused positions are filled with leading zeros.

Module 2

Negative numbers and signed or unsigned ranges

A register is just a row of bits, so a decision is needed about what the pattern means. Treat every bit as part of the magnitude and the number is unsigned. Reserve some way to mark a negative number and it is signed. There are two ways to do that.

1. Sign bit (sign-magnitude)

The Most Significant Bit (MSB) becomes the sign bit. 0 means positive and 1 means negative. The remaining 7 bits of an 8-bit register store the magnitude.

  • (+7)10 → 0000 0111. The MSB is 0, so the number is positive.
  • (−7)10 → 1000 0111. The MSB is 1, so the number is negative. The magnitude bits 0000111 are unchanged.

Limitation: two zeros

Sign-magnitude has both +0 = 0000 0000 and −0 = 1000 0000.

  1. One value takes up two bit patterns, which wastes a pattern. With 7 magnitude bits the range is only [−127, +127], which is 255 different numbers from 256 patterns.
  2. The ALU needs extra logic. An adder has to look at both sign bits and decide whether to add or subtract the magnitudes, and a comparison has to treat +0 and −0 as equal.

2. 2’s complement

2’s complement fixes both problems. There is only one zero, and subtraction becomes addition, so the same adder circuit handles positive and negative numbers. To negate a number:

  1. Take the 1’s complement: invert every bit.
  2. Add 1 to the result. This is the 2’s complement.

For example, (−7)10 in 8 bits: 0000 0111 inverts to 1111 1000, and adding 1 gives 1111 1001.

The MSB still tells the sign, but in an n-bit register it carries the weight −2n−1 instead of a flag. In 4 bits, 1101 = −8 + 4 + 1 = −3.

Subtraction as addition. To compute 5 − 3 in 4 bits, add 5 and −3. The pattern for −3 is the 2’s complement of 0011, which is 1100 + 1 = 1101. Then 0101 + 1101 = 1 0010. The carry out of the top bit is discarded, leaving 0010 = 2.

Worked boundary example: 1000

Start with the 4-bit pattern 1000. Its 1’s complement is 0111. Adding 1 gives 0111 + 1 = 1000, the pattern we started from. A number whose negation is itself must be the one with no positive counterpart, so 1000 is −8. The matching +8 would need a fifth bit, which is why a 4-bit signed range has one more negative value than positive values.

3. Ranges for 4 bits and 8 bits

An n-bit register has 2n bit patterns. Unsigned numbers use them all for 0 upward. Signed 2’s complement splits them between negatives and non-negatives.

Bitwise logical operations and logic gates

A bitwise operation takes two registers and applies the same logic to each pair of bits that sit in the same position, so an 8-bit operation is really eight independent gates side by side. Five operations are used constantly.

XORing with 1 flips a bit and XORing with 0 leaves it, so XOR toggles the bits chosen by a mask. With X = 1001 0101 and the mask 0000 1111 the result is 1001 1010. Applying the same mask again restores X. Two more facts follow from the table. X ^ X = 0000 0000, and X ^ 0 = X.

Parity. XOR also computes parity, which is the idea behind Module 4. XORing a set of bits gives 1 when the number of 1s is odd. For the data bits 1111 000 the chain is 1 ^ 1 ^ 1 ^ 1 ^ 0 ^ 0 ^ 0 = 0, so the even-parity bit is 0. For 1011 000 the chain gives 1, and the parity bit is 1.

Module 4

Error detection with parity bits

Concept and mechanism

Noise on a wire, or a fault in memory, can flip a bit, so a system needs a cheap way to notice that data has changed. The simplest scheme appends one extra bit, the parity bit, to the data before it is transmitted. The transmitter chooses that bit so that the total number of 1s in the whole word, data bits plus parity bit, has an agreed parity.

  • Even parity: the total count of 1s is even.
  • Odd parity: the total count of 1s is odd.

The receiver recounts the 1s in the word that arrives. If the count no longer has the agreed parity, it raises an error flag.

Data (7 bits)SchemeParity bitTransmitted word1s in word
1111 000even01111 00004 (even)
1111 000odd11111 00015 (odd)

Worked example 1: a single-bit error is detected

The transmitter sends the data 1111 000 with even parity. It holds four 1s, which is already even, so the appended parity bit is 0 and the word on the wire is 1111 0000.

Noise flips the second bit and the receiver gets 1011 0000. It counts three 1s. Three is odd, which breaks the even-parity rule, so the receiver raises an Error flag.

Worked example 2: a two-bit error is missed

The transmitter again sends 1111 0000. This time noise flips two bits and the receiver gets 1001 0000. The word now holds two 1s. Two is even, which is exactly what the receiver expects, so the check passes and the corrupted word is accepted.

Every flip changes the count of 1s by exactly one, up or down. One flip always turns an even count into an odd one. A second flip changes it by one more and puts the parity back. Any even number of flips cancels out in the same way.

Core limitations

  1. Parity cannot identify which bit position flipped. It can detect that something changed but cannot correct it.
  2. If 2 bits flip, or any even number of bits flip, the parity is unchanged and the error goes undetected.

Module 5

Bit masking: clear, set and field extraction

Bit clear and field isolation with AND and a shift

A mask is a bit pattern combined with a value one bit position at a time. The mask decides, position by position, whether a bit is forced to a fixed value or left alone.

Mask bitx AND maskx OR mask
00 (bit cleared)x (bit kept)
1x (bit kept)1 (bit set)

So AND clears the bits you do not want to zero and preserves the target field. A right shift then moves that field to the least significant end so it can be read as an ordinary number.

Worked example: extract bits 4–2

Take x = 10010100. The middle three bits, 101 in bit positions 4, 3 and 2, are the field we want.

  1. Build the mask. Put 1s over bits 4–2 and 0s everywhere else: 00011100.
  2. Apply AND. 10010100 AND 00011100 = 00010100. Every bit outside the field is cleared. The field is still sitting in bits 4–2.
  3. Shift right by 2. There are two bits below the field, so 00010100 >> 2 = 00000101. The field is now aligned at the LSB and reads 1012 = 5.

Try problem: identify each operation

A value goes through three transformations. For each step, work out which operation turned the previous value into the next one.

StepResultOperationMask or amountReason
Start00101010initial value
111101010Bit set (OR masking)| 11000000Bits 7 and 6 went from 0 to 1 and nothing else moved. OR with 1 forces a bit to 1, OR with 0 leaves it.

A quick way to spot the operation is to compare the two values bit by bit. Bits turning from 0 to 1 while the rest stay put point to OR. Bits turning from 1 to 0 point to AND. A whole pattern sliding sideways points to a shift.

Module 6

Shift operations: logical, arithmetic and cyclic

A shift moves every bit of a register a fixed number of places left or right. The three kinds differ in two things: what fills the positions that become empty, and what happens to the bits pushed off the end.

1. Logical shift

A logical right shift moves each bit one place toward the LSB. A 0 enters at the MSB and the old LSB falls out. A logical left shift is the mirror image: a 0 enters at the LSB and the old MSB falls out.

4-bit right shift. Start with n = 0111. After n >> 1 the register holds 0011, and after n >> 2 it holds 0001.

Right shift divides by 2n

Shifting right by n places divides an unsigned number by 2n. To divide a binary number using right shift, the divisor must be in the form of 2n.

Take (20)10 = 00010100, which is 16 + 4 using the weights 128, 64, 32, 16, 8, 4, 2, 1. To divide by 4:

204 = 2022 = 5, so n = 2

Shift right by 2: 00010100 (20) → 00001010 (10) → 00000101 (5). The two rightmost bits are shifted out, and here both are 0, so nothing is lost.

Notation check

Division by 22 uses the right-shift operator, n >> 2. The shorthand n << 2 that appears above this diagram in the handwritten notes would multiply by 4, so read it as n >> 2.

When the bits that fall out are not all 0, the result is the integer quotient with the remainder discarded. For example 00010101 (21) >> 2 gives 00000101 (5), not 5.25.

Left shift multiplies by 2n

Shifting left by n places multiplies by 2n. To compute 20 × 8 = 20 × 23 = 160, shift left by n = 3.

00010100 (20) → 00101000 (40) → 01010000 (80) → 10100000 (160).

The result must still fit in the register. An 8-bit unsigned register tops out at 255, so 00010100 << 4 would need 320 and instead leaves 01000000 (64) because the top 1 is shifted out.

2. Arithmetic shift (MSB fixed)

Numbers in two's complement keep their sign in the MSB. A logical right shift would put a 0 there and turn a negative number positive: 10110100 (−76) would become 01011010 (+90). An arithmetic right shift avoids that by keeping the MSB fixed. The sign bit is copied into the vacated left positions instead of zeros.

Worked example. Start with x = 10110100. One step gives 11011010 and a second gives 11101101. Read as two's complement, the values are −76, −38 and −19, so each step halves the number and keeps its sign.

Arithmetic left shift is the same as logical left shift. The lecture also writes the arithmetic right shift as x >>> 2. Notation differs between languages: Java and JavaScript use >> for arithmetic and >>> for logical, so check your language’s rule before relying on the symbol.

For odd negative numbers the right shift rounds toward −∞: 11111101 (−3) >> 1 gives 11111110 (−2).

3. Cyclic shift (bit rotation)

In a cyclic shift, bits pushed out of one end re-enter at the opposite end, so no data is lost. Rotating right sends the LSB around to the MSB.

Worked example. Take the 4-bit register n = 0111. One rotation to the right gives 1011 and a second gives 1101. After four rotations the register is back at 0111.

Many textbooks write the rotate operators as ROR and ROL to separate them from the plain shifts. The labels in the figure follow the lecture notation.

Module 7

Real numbers and fixed-point representation

Anatomy of a real number

A real number such as 40.25 has an integer part (40), a decimal or radix point (.) and a fraction part (25). In fixed-point representation the radix point is never stored. The hardware and the programmer agree on a fixed split of the register into integer bits and fraction bits, so the point always sits in the same place. Fixed-point comes in two forms, unsigned and signed.

Unsigned fixed-point: 8 bits as 4 INT + 4 FRACTION

Convert (7.5)10. Handle the two parts separately.

  • Integer part: 7 = 4 + 2 + 1, so in four bits 7 = 0111.
  • Fraction part: multiply by 2 repeatedly and record the integer part that appears each time.
StepMultiplyResultBit recorded
10.5 × 21.01
20 × 200

The fraction is now 0, so the remaining fraction bits are 0 as well: 0.5 = .1000. Joining the parts gives 0111.1000, which is the register [0|1|1|1|1|0|0|0]. The INT field can hold values from 0 to 15.

Fractional precision and bounds

The four fraction bits carry the weights 2−1, 2−2, 2−3 and 2−4, which are 0.5, 0.25, 0.125 and 0.0625.

minimum non-zero fraction = (.0001)2 = 1 × 2−4 = 0.0625

maximum fraction = (.1111)2 = 2−1 + 2−2 + 2−3 + 2−4 = 0.9375

Together with the 4-bit integer part, the whole format spans 0 to 15.9375 in steps of 0.0625.

Signed fixed-point: (−7.5)10 = (−111.1000)2

Two complement rules are needed. The 1's complement inverts all bits. The 2's complement adds 1 to the least significant bit of the 1's complement.

Approach 1: sign-magnitude

Spend bit 7 on the sign (0 means positive, 1 means negative), bits 6–4 on the integer part (0 to 7) and bits 3–0 on the fraction. For −7.5 the sign is 1, the integer part is 111 and the fraction is 1000, giving [1|1|1|1|1|0|0|0].

Approach 2: 2's complement

  1. Write the positive value: (+7.5)10 = 0111.1000.
  2. Take the 1's complement by inverting every bit: 1000.0111.
  3. Take the 2's complement by adding 1 at the LSB: 1000.0111 + 1 = 1000.1000. The carry ripples up through the fraction bits.
  4. The final register is [1|0|0|0|1|0|0|0], with INT = 1000 and FRACTION = 1000.

Check. In 2's complement the MSB has weight −8, so 1000.1000 = −8 + 0.5 = −7.5. Approach 1 reserves one bit for the sign and leaves only 3 integer bits, while approach 2 keeps all 4 integer bits and builds the sign into the number.

Module 8

Bias notation (excess-K representation)

Why bias notation exists

Signed numbers are normally stored in 2's complement, but compared as plain unsigned bit patterns the negative ones look larger than the positive ones. Bias notation adds a constant K to every value so the whole signed range is shifted up into non-negative codes. The codes then sort in the same order as the values they represent, and ordinary unsigned hardware can compare them. Floating-point exponents are stored this way for exactly that reason.

Number lines for a 4-bit system

With 4 bits the signed range is −8 to +7 and the unsigned range is 0 to 15. Both have 16 positions. Lining them up shows that biasing by 8 moves each signed value to the unsigned code directly below it.

Why raw comparison fails

Encodingx = +1y = −1Read as unsignedHardware concludesCorrect?
2's complement000111111 and 15y > xNo, since −1 < +1
Bias = 8100101119 and 7x > yYes

Bias formula

Bias = 2n−1

For n = 4 bits, Bias = 24−1 = 23 = 8.

Lecture bias versus IEEE 754

The lecture's excess-2n−1 gives 8 for 4 bits and shifts the range to −8 … +7. IEEE 754 uses 2n−1−1, which is 7 for 4 bits (127 for an 8-bit exponent) and shifts the range to −7 … +8.

Encode and decode (4 bits, bias = 8)

  • Encode by adding the bias and writing the sum with weights 8, 4, 2, 1. Encode 1: 1 + 8 = 9 → 1001. Encode −1: −1 + 8 = 7 → 0111.
  • Decode by reading the bits as an unsigned number and subtracting the bias. Decode 1001: 9 − 8 = 1. Decode 0111: 7 − 8 = −1.

Floating-point representation

Precision formats

Floating-point stores a number as a sign, a biased exponent and a mantissa, much like scientific notation in base 2. The more bits, the larger the range and the finer the precision.

Label check

The handwritten note labels 16 bits as Single and 32 bits as Half. In IEEE 754, Half is 16 bits and Single (float) is 32 bits. The 1 + 8 + 23 = 32 diagram in the notes is single precision, and that is the format used for every problem below.

32-bit register architecture

  • Sign bit (1 bit): 0 means positive, 1 means negative.
  • Biased exponent (8 bits): the power of 2 plus a bias, stored as an unsigned number (Module 8).
  • Mantissa or fraction (23 bits): the bits after the leading 1. That leading 1 is always present after normalizing, so it is not stored.

Exam problem 1: convert (12.625)10 to 32-bit floating point

Start from the binary form (12.625)10 = (1100.101)2. The integer part 12 = 8 + 4 is 1100. For the fraction 0.625, 0.625 × 2 = 1.25 gives 1, 0.25 × 2 = 0.5 gives 0, and 0.5 × 2 = 1.0 gives 1, so it is .101.

  1. Sign bit. The number is positive, so the sign bit is 0.
  2. Normalize. Move the radix point left 3 places so one 1 remains in front of it: (1100.101)2 = 1.100101 × 10002 = 1.100101 × 23.
  3. Mantissa (23 bits). Drop the leading 1. and keep 100101. Pad on the right with 17 zeros: 10010100000000000000000.
  4. Biased exponent (n = 8 bits). Add the bias to the exponent 3 and convert with the weights 128, 64, 32, 16, 8, 4, 2, 1.
