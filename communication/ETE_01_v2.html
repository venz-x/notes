Module 1

Components and protocols

Definition

Data communication is the exchange of data between two devices through a transmission medium. It always involves five components.

Every exchange needs a device that creates data, a device that receives it, a path between them, the data itself, and a set of agreed rules. If one of the five is missing or mismatched, communication fails.

#ComponentWhat it is
1SenderThe device that originates and transmits the data (a computer, phone, or server). It formats the message according to the protocol before sending.
2ReceiverThe device that receives the data and interprets it using the same protocol rules the sender used.
3Transmission MediumThe physical path that carries the signal from sender to receiver (twisted-pair cable, fiber, or radio waves).
4Data / MessageThe Actual Data (Payload) being communicated: text, numbers, audio, video, or images.
5Rules / ProtocolsThe agreed-upon rules that govern the communication. Without them two devices cannot understand each other.

Protocol

Definition

A protocol is a set of agreed-upon rules that govern the entire communication process.

In practice, protocols are implemented as a protocol stack: layered software and hardware in which each layer handles one part of the rules (formatting, addressing, delivery). Both endpoints run the same stack.

Protocols decide:

  • What type of message can be sent, and what format or structure it must follow.
  • When a message may be sent, and how the receiver should interpret it.
  • How the sender and receiver identify each other across the network.
  • How lost, damaged, delayed, or duplicate messages are handled, and how to confirm that communication was successful.

The three key elements of a protocol

ElementMeaningDetails
Syntax (Formatting)Defines how the data must be formatted or arranged.Data is organised into fields and bit patterns, such as header fields followed by the payload.
Semantics (Meaning)Defines the meaning of each field.How a particular pattern is interpreted, and what action follows from it.
TimingGoverns when and how fast data moves.(i) when data should be sent; (ii) how long to wait for a response; (iii) when to resend; (iv) how fast data can be sent, regulated by a flow control protocol.

Module 2

Data flow (transmission modes)

Definition

Data flow describes the direction in which data travels between two devices. There are three modes: Simplex, Half-Duplex, and Full-Duplex.

The mode depends on whether each device can transmit, receive, or both, and whether it may do both at once. The choice trades off cost and capacity: more simultaneous directions need more channel capacity.

ModeHow it worksExample
SimplexData flows in one direction only, from Sender (S) to Receiver (R). The receiver cannot transmit back.Television (TV) broadcasting
Half-DuplexData flows in both directions, but only one direction at a time. The link is shared, so devices take turns.Walkie-talkies, two-way radios
Full-DuplexData flows in both directions simultaneously. Both nodes can send and receive at the same moment.Modern communication such as smartphones

Q1: Identify the scenario based on data flow

(a) A radio station transmits a music program; listeners tune in but cannot send anything back through the same channel. Which mode?

(b) Two security guards use handheld radios; one must release the button before the other can speak. Which mode?

(c) Two friends talk on a phone call and can hear each other while both speaking. Which mode?

Answers: (a) Simplex, one-way only. (b) Half-Duplex, both directions but alternating. (c) Full-Duplex, simultaneous both ways.

Module 3

Data representation

Definition

Computers and networks transmit all information as binary (0s and 1s). Text, Numbers, Audio, Video, and Images must each be converted to binary before transmission.

Text and numbers

Text characters are mapped to binary numbers using ASCII (American Standard Code for Information Interchange). Each character has a numeric code, stored as a bit pattern. Numerical data is represented directly in binary (base 2).

Audio and analog-to-digital conversion (ADC)

Lecture question: How is audio converted to a digital signal?

An analog signal takes continuous values over time t, while a digital signal takes discrete values over time t. An ADC (Analogue to Digital Converter) turns the first into the second in three steps.

StepProcess
1. SamplingThe analog signal is measured at regular time intervals, giving a series of amplitude samples.
2. QuantizationEach sampled amplitude is rounded to the nearest of a finite set of discrete levels.
3. EncodingEach quantised level is assigned a binary code (bit pattern), producing the digital bit stream for transmission.

Images and pixel depth

Definition

A pixel (picture element) is the smallest addressable unit of a digital image.

An image is a grid of pixels, and each pixel is stored as a binary pattern. The number of bits per pixel (pixel depth) decides how many intensity or colour values a pixel can take.

Image typeBits per pixelDescription
Monochromatic / Binary (Black and White)1 bitEach pixel is strictly 0 (black) or 1 (white).
Grayscale8 bits28 = 256 intensity shades from black to white.
Color / RGB24 bitsThree equal 8-bit channels: Red (8 bits), Green (8 bits), Blue (8 bits).

Module 4

Data communication characteristics and a case study

Definition

The effectiveness of a data communication system depends on four criteria: Delivery, Accuracy, Timeliness, and Jitter.

CharacteristicDefinitionMechanics
(i) DeliveryData must be delivered only to the correct, intended destination device or user.Addressing in the protocol identifies the destination. Wrong addressing sends data to unintended recipients.
(ii) AccuracyData must arrive unaltered. Corrupted or damaged data in transit is unusable.Noise or faults can flip bits during transit, so the received data differs from what was sent.
(iii) TimelinessData must be delivered rapidly enough to remain useful, without minutes-long delays that stall operations.Information has a useful lifetime. Late delivery can make it worthless.
(iv) Jitter ***
(high priority)		The variation in delays between packet arrival times. Crucial for real-time audio and video.Packets sent at uniform intervals but arriving at uneven intervals give choppy playback even if the average delay is low.

Applied case study

Scenario

A company recently implemented a new data communication system for internal use. However, users have reported several issues during daily operations. Which data communication characteristics were violated?

Case 1

"Important notifications and updates often take several minutes to arrive, delaying critical decision-making."

Violated characteristic: Timeliness. Delivery succeeded, but too late to be useful. Delays of several minutes stall operations and force decisions on outdated information.

Case 2

"Some sensitive messages were received by employees who were not supposed to receive them, causing privacy concerns."

Violated characteristic: Delivery. Misrouted packets reached unintended recipients. Delivery requires data to reach only the correct, intended destination, so reaching the wrong people is a failure even if the data is intact and fast.

Case 3

"Files sent between team members arrived corrupted, making them unusable."

Violated characteristic: Accuracy. Bits were altered during transit, so the received file no longer matches the original. Corrupted data is unusable, so data integrity was destroyed.

Case 4

"During video conferences, the audio and video seem unsmooth."

Violated characteristic: Jitter. Packets arrived at uneven intervals (variation in delay between arrivals). Real-time media needs steady arrival to play smoothly, so uneven gaps cause choppy playback.
